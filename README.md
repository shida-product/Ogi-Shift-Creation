# Ogi Shift Creation — オオギ薬局 シフト管理・自動生成

> 対象: 恵比寿店・渋谷店の希望休収集から勤務シフト作成、勤怠取込用CSV出力まで  
> ドキュメント確認日: 2026-10-09（GitHub `main` 上のコード・仕様との照合。実機／本番DBの動作確認は未実施）

## 概要

スタッフがPC（ガントチャート）またはスマートフォン（カレンダー）から希望を登録し、管理者が**明示的な勤務条件に基づくルールベースの生成処理**でシフト案を作成するWebアプリです。生成後は制約充足状況を確認し、画面上で修正、勤怠管理サービス向けCSVを出力できます。

- 対象: 2店舗、スタッフ約8名（構成・条件は運用環境に依存）
- 生成方式: ルールベースの貪欲法・スコアリング。30パターンを試行し、最高スコア案を採用
- **生成AI／機械学習によるシフト決定は行いません**
- Ogiで月次業務に1年以上継続利用（運用者申告）
- 作成者の月次作業時間: 導入前約3〜4時間 → 導入後約15〜30分（運用者概算。転記・確認・調整込み）

## 画面・主要機能

| 画面 | 主な機能 |
| --- | --- |
| `login.html` | Supabase Auth のメール・パスワードログイン |
| `index.html` | PCガント／スマホカレンダーでの希望休・勤務確定・条件付き希望の登録、月移動 |
| `generate.html` | 自動生成、条件チェック、ガント表示、セル単位の手動調整、Undo/Redo/Reset、生成時点との差分確認、CSV出力 |
| `admin.html` | スタッフ追加・編集、有効状態・配属・勤務条件・優先順位、月別公休数の管理 |

`index.html`、`generate.html`、`admin.html` は `js/auth.js` によるセッション確認とログアウト導線を持ちます。**画面上のログイン制御とDBのアクセス制御は別の問題**です。現在の本番SupabaseのRLSポリシーは未確認のため、本番の保護状態をこのREADMEだけで保証しません。

### 希望登録・対象月

- 希望区分: 休み、調剤、午前可、午後可、その他、恵比寿／渋谷への勤務確定など
- 勤務確定は生成処理で最優先に配置。ただし他制約との矛盾は警告として示す場合があります
- 初期表示: 希望入力は毎月1〜15日が翌月、16日以降が翌々月。生成画面は翌月
- 過去月の参照と先の月の表示範囲は `js/month-window.js` を共通利用。16日以降は当月から5か月先までの開放ルール

### 自動生成と調整

- 店舗の必要人数、希望休、既定勤務日、個別連勤上限、公休数、勤務日数上限などを扱います
- 必須条件（ハード制約）と望ましい条件（ソフト制約）を区別。条件が衝突する場合は警告が残ることがあり、**必ず全条件を満たすことを保証するものではありません**
- `runAllChecks()` の結果を生成案の採点と画面の条件チェックに共用
- 生成直後のシフトは `ogi_shift_generated_assignments` に、手動調整後の現行シフトは `ogi_shift_assignments` に保持し、差分を表示・CSV出力できます
- Undo/Redo と Reset に対応。再生成時には新しい生成案を採用し、既存の手動変更フラグをリセット
- DB側の最新シフトを表示上の正とし、複数端末からの変更を取り込む設計

> 個人名を含む勤務条件と優先順位の**現行仕様**は `docs/shift-generation-requirements.md` を参照してください。新規顧客へ流用する場合は顧客固有の条件・データを分離してください。

### マネーフォワード向けCSV

`js/generate.js` にCSV出力処理があり、従業員番号・氏名・日付・勤怠区分・勤務パターン等を出力します。ブラウザ側で `encoding-japanese` をロードし、Shift-JISへ変換します。出力は **CSVファイルを介した取込向け** であり、マネーフォワードへのAPI直接同期ではありません。取り込み側の従業員番号・勤怠区分・勤務パターン設定との整合を運用時に確認してください。

## ローカル確認

1. `js/supabase-config.sample.js` を参考に、環境ごとの接続設定を用意します。**本番用の設定・認証情報・実スタッフデータをデモ環境へ流用しないこと。**
2. 静的HTTPサーバーで起動します。ES Modulesを使用するため、ファイルの直接オープンは想定しません。

```bash
npx -y http-server -p 8000 -c-1
```

3. `http://localhost:8000/login.html` からアクセスします。
4. コードの既存テストは以下で実行できます。

```bash
npm test
```

- 実スタッフの勤務希望・シフト情報を取り扱います。権限を確認せず本番DBや勤務条件を変更しないでください
