# オオギ薬局 シフト作成ツール

## プロジェクト概要
オオギ薬局（恵比寿・渋谷）のスタッフ約8名が、スマートフォンやPCから毎月の「希望休」を提出し、それをもとにルールベースのアルゴリズムがシフト案を自動生成するWebアプリケーション。

## 画面構成

### メイン画面（`index.html`）
- **PC**: ガントチャート形式。ドラッグで複数日一括選択して希望休を登録。
- **スマホ**: カレンダー形式。日付タップで詳細表示・登録。
- 7種類の希望に対応（休み希望 / 調剤 / AM可 / PM可 / その他 / 勤務（恵比寿）/ 勤務（渋谷））
  - 「調剤」は徳永専用。別薬局での勤務日を登録し、連勤制御に使用。
  - 「勤務（恵比寿）/（渋谷）」は勤務が確定している日。全スタッフ共通で、希望休と同列のハード制約として生成に反映される（勤務日数にも算入）。
- 画面下部に「条件付き・その他の希望」リスト表示
- **月の表示・開放**（`js/month-window.js` 共通）
  - 初期表示: 1〜15日→翌月、16日以降→翌々月（編集ロックなし）
  - ナビ／ピッカー: 2026-04〜各月16日以降は約半年先（+5ヶ月）まで開放（例: 8/16〜9/15は翌1月まで、9/16〜10/15は翌2月まで）

### シフト生成画面（`generate.html`）
- 月を選択してシフトを自動生成（30パターン試行→最高スコア採用）
- 希望休画面と同じ月窓・初期表示ルール
- Undo/Redo/Reset機能で手動調整の履歴管理
- ガントチャートで結果表示（希望休はストライプ背景で種類別に色分け）
- セルクリックで手動微調整（ドロップダウン）
- **生成直後をDBに保存**し、手直しとの差分を画面とCSVで確認できる
- 画面下部の**条件チェックパネル**で全スタッフの制約充足状況を自動判定
- CSV出力（Shift-JIS、マネーフォワード連携用）

### 管理画面（`admin.html`）
- スタッフの追加（職種・区分・配属を同時設定）
- 編集モーダル（勤務条件・店舗優先順位の詳細設定）
- 表示順の並び替え（▲▼ボタン）
- 有効/無効の切り替え
- 月別公休数の設定（2年分一覧、変更時自動保存）
- テスト用データリセット機能

## シフト生成アルゴリズム

ルールベース貪欲法（30パターン試行→最高スコア採用）で**決定論的に**自動生成。
AI/機械学習は使用しておらず、全てのルールは明示的にコード内で定義されている。
詳細な制約条件は [`docs/shift-generation-requirements.md`](docs/shift-generation-requirements.md) を参照。

### アーキテクチャ（`js/generate.js`）
```
runAllChecks()  ← 全チェック項目を実行し構造化データを返す共通エンジン
  ├── scoreShifts()          ← スコアを算出（生成時の比較用）
  └── renderConditionsCheck() ← UIパネルに結果を描画
```
- チェックロジックは `runAllChecks()` に一元化されており、スコアリングとUI表示の整合性を保証
- ヘルパー関数（`_workDays`, `_maxConsecutiveWork` 等）はモジュールレベルで共有

### 生成の流れ
0. 勤務確定（`work_ebisu` / `work_shibuya`）を各日の先頭で配置。以降のロジックは一切上書きしない（手動調整のみ上書き可）
1. 社員（小野・信太）の公休日を事前計算（希望休反映→日曜定休→残りを分散配置。勤務確定日は公休候補から除外）
2. 小野・信太を各日に配置（信太は○渋谷。◯開発の自動切替は停止中）
3. 事務パートを**負債（debt）ベース**で均等配置（月全体にインターリーブ）
4. 徳永は事務確定後に実人数で1回だけ配置（薬不足→薬1、事務0→薬2、それ以外は休。17日未達OK / MAX22日）
5. 村上は店舗に自動配置しない（希望休のみ所定休日として反映。不足は警告のみ）
6. 常に今回の最高スコアの生成結果を採用し、前回の手動調整フラグなどはリセットされる（気に入らなければUndo/Reset機能で戻す運用）

### 主要な制約（概要）
- **ハード制約**: 店舗充足、希望休・調剤反映、勤務確定反映（店舗指定込み）、連勤上限（個別設定）、調剤含み連勤、店舗固定、公休数、勤務日数上限
  - 勤務確定は他のハード制約より優先。結果として連勤上限や公休数を超える場合は、生成を止めず条件チェックパネルの警告で示す
- **ソフト制約**: 信太↔小野の非重複、小野の日曜隣接2連休、信太の連休分散、事務の店舗固定とペース配分、徳永の店舗選択
- **運用停止中**: 信太◯開発の自動切替、村上の自動穴埋め（いずれも手動は可）
